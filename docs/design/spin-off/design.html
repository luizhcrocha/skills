Spin-off: hand complex work found mid-session to a designer, then to a fleet

An agent that finds work too big for its current task proposes a spin-off. On your yes, a designer session (Opus high) opens in a new Rex tab. It researches, models and draws the work until you approve three things: the design, the lane plan and the team. Then it starts the coordinators and its job ends. The origin agent keeps its own task the whole time.

v3 takes in a Fable advisor's ruling ("go with changes"). Its changes are marked below. Your three approvals of v2 are void under the design's own rule, so they are asked again at the end.

Data shapes

The origin writes one file outside the repo, as handoff does, so it never lands in its own open change. The designer copies it into its own jj workspace. Everything lands as docs before launch, so coordinators' workspaces see it. Missions are one line of at most 2,000 characters (fleet team add --help), so they point at these paths.

Changed in v5 (review and a real run)

  • A team change goes back through the fleet check before gate 3 asks again. v3 sent it straight to review, so a renamed coordinator could clash unseen.
  • Gate 3 can create a project. When no fleet project fits, team.md names a new id and gate 3 offers: approve and create it, change the team, or drop. fleet project new "<title>" --id <id> runs once on your typed yes.
  • An untrusted repo shows you the exact fleet team add … --trust line; it runs once on your typed yes. A refusal is reported, never retried.
  • The no-fleet path rechecks the record and lands the docs before it opens the orchestrate tab.
  • The design hash covers the whole design folder (all but dossier, plan and team), so an edited .tla or ADR voids the design too.
  • Required skills are named: show-me for the page, domain-modeling for ADRs and terms, statechart when the work moves between states. A real claude -p run had skipped them all.
  • Headless fallback: with no AskUserQuestion, the designer asks the gate in its reply and records nothing. The real run did exactly that and stopped at gate 1 with no approval.

What the advisor changed

  • Approvals live in the record, not in memory. The v2 model kept the plan's approval after a design change; only the session's phase forced the re-ask, and a compacted designer would lose it.
  • The designer has its own jj workspace. A tab in the origin's workspace would snapshot design files into the origin's open change. Your CLAUDE.md forbids shared workspaces.
  • The tab opens with rex run, not fleet team add. fleet team takes only coordinator and manager roles, starts them at Opus medium, and a ledger in the opening turns the session into a coordinator. Outside Rex, the origin prints the command for you in nushell.
  • One fleet team add per coordinator, run by the designer itself, since its yes is first-hand and a relayed yes is not (fleet manager skill). No "register with the manager": the manager greets new fleets, and the FYI goes to fleet news.
  • The fleet check comes before gate 3, so you never approve a team whose names or files clash. With fleet down, the designer parks there.
  • Fable is a Decider, not the fleet advisor. fleet advisor needs a ledger the designer does not have.
  • Renames. brief.md became spin-off.md (the fleet already has a brief.md); "landing order" became "dependency order" (landing order is the manager's).
