# Deep review

The [review](SKILL.md) pass that tries to break the change, for a contested design, a risky diff, or the areas the fleet plugin's coordinator names in its Review levels (INTEGRATE.md). It replaces the two axes and uses step 1's diff command and `Read:` list. Adapted from pstack's interrogate (poteto, MIT): a finding survives only when a run proves it.

1. **State the intent.** One paragraph from the user's message, the change descriptions and the spec (step 2). Unsure: ask before spawning.
2. **Three finders in parallel.** `general-purpose` Reviewers ([models.md](../../../docs/models.md)), one per angle: security; concurrency and state; spec and tests. Each gets the intent, the diff command, the repo's REVIEW.md and its own jj workspace at the stack's head, and this brief: "Break this change. Prove each finding with a run against the real code: a failing test in the repo's own test tools, or the output of the repo's own command. Report the title, the exact command, the output it printed, the output the intent requires, and `Caught by:` the cheapest check that would have caught it with no reader (`type`, `lint`, `test`, `property`, `model` or `none`). Leave out style, naming, structure and risks that need a future change to matter. A claim you could not run goes under Unproven with why. No findings is a valid result."
3. **One verifier.** A fresh Verifier ([models.md](../../../docs/models.md)) reruns each command in the finder's workspace. A finding stays when the output shows the failure and the failure breaks the intent. Merge findings that share a root cause.
4. **Report.** The intent; the verified findings, which are Important, each with its command, output, how it breaks the intent and the finders that found it; Unproven, each with its trace (file and line) when it has one, so a real risk no one could run is not lost; for each finder, the count dropped and why; the `Read:` line. Apply nothing. Outside a fleet the user decides; in a fleet the coordinator sends the Important findings to a FIX round and rules on each Unproven claim, as a FIX, a follow-up or a decision for Luiz. A verdict line ends the report: LAND, or FIX when an Important finding stands.

A proof is a test in the repo's own tools. No standalone attack or forging scripts: a safety classifier refused them on 2026-10-16, and a refused act is never routed around. Delete the finders' workspaces after the report, keeping any test the fix adopts. Record it per [LEDGER.md](LEDGER.md), with the verified findings and the Unproven claims in `--findings`, and only the verified ones in `--proven`.
