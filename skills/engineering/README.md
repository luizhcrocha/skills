# Engineering

Skills I use daily for code work.

- **[diagnosing-bugs](./diagnosing-bugs/SKILL.md)** — Disciplined diagnosis loop for hard bugs and performance regressions: build a feedback loop that goes red on this bug → minimise → hypothesise → instrument → fix → regression-test.
- **[grill-with-docs](./grill-with-docs/SKILL.md)** — Grilling session that challenges your plan against the existing domain model, sharpens terminology, and updates `CONTEXT.md` and ADRs inline.
- **[triage](./triage/SKILL.md)** — Triage issues through a state machine of triage roles.
- **[improve-codebase-architecture](./improve-codebase-architecture/SKILL.md)** — Scan a codebase for deepening opportunities, present them as a visual HTML report, then grill through whichever one you pick.
- **[codebase-design](./codebase-design/SKILL.md)** — Shared vocabulary and principles for designing deep modules — module, interface, depth, seam, adapter, leverage, locality — used directly or pulled in by other skills.
- **[domain-modeling](./domain-modeling/SKILL.md)** — Actively build and sharpen a project's domain model: challenge fuzzy terms, capture the glossary in `CONTEXT.md`, and record hard-to-reverse decisions as ADRs inline.
- **[setup-luizrocha-skills](./setup-luizrocha-skills/SKILL.md)** — Scaffold the per-repo config (issue tracker, triage label vocabulary, domain doc layout) that the other engineering skills consume. Run once per repo before using `to-issues`, `to-spec`, `triage`, `diagnosing-bugs`, `review`, `tdd`, or `improve-codebase-architecture`.
- **[migrate-to-agents-md](./migrate-to-agents-md/SKILL.md)** — Move a repo's agent instructions from `CLAUDE.md` into `AGENTS.md`, which Claude Code now reads natively, so every coding agent reads one file and no `CLAUDE.md` shadows it: inventory, a per-directory plan with merges you approve, references updated, `/memory` check.
- **[research](./research/SKILL.md)** — Investigate a question against high-trust primary sources and capture the findings as a cited Markdown file in the repo, run as a background agent.
- **[resolving-merge-conflicts](./resolving-merge-conflicts/SKILL.md)** — Resolve conflicts by intent, jj first: a conflicted change is read side by side (each side's change, its pre-rebase version through `jj evolog`, their PRs, `why` when unclear), resolved in a child and `jj squash`ed into it, then the repo's checks run. Plain git merges and rebases have a fallback section (never `--abort`).
- **[tdd](./tdd/SKILL.md)** — Test-driven development and choosing the evidence: pick the rung of the testing ladder the risk needs, then red-green one vertical slice at a time, with substitutes only through seams and the evidence tier reported.
- **[implement](./implement/SKILL.md)** — Build the work described by a spec or set of issues, driving `/tdd` at pre-agreed seams and closing out with `tstack:review`, recorded as described jj changes (`jj describe`, `jj new`; the worktree-janitor for a messy `@`).
- **[review](./review/SKILL.md)** — Two-axis review of the diff since a fixed point (by default the landing bookmark's remote, through jj): **Standards** (does it follow the repo's coding standards, plus `lang-ts` for TypeScript and the Fowler smell baseline?) and **Spec** (does it faithfully implement the originating issue/spec?), run as parallel Opus sub-agents so neither pollutes the other. Renamed from `code-review`, which Claude Code's built-in takes.
- **[interrogate](./interrogate/SKILL.md)** — Adversarial review: three fresh Opus reviewers, each on its own lens (correctness and security; maintainability, with thermo-nuclear's code judo and spaghetti rules; intent and spec), try to break a change, and the lead sorts their findings into Act on / Consider / Noted / Dismissed with an agreement map. Never applies changes. Adapted from poteto's pstack and cursor-team-kit (MIT).
- **[blast-radius](./blast-radius/SKILL.md)** — Find what a change breaks beyond the diff (library internals, timing, wire formats, other readers of the same bytes) and prove the one fact it is safe because of by running real code. Adapted from poteto's pstack.
- **[to-issues](./to-issues/SKILL.md)** — Break any plan, spec, or PRD into independently-grabbable GitHub issues using vertical slices.
- **[to-spec](./to-spec/SKILL.md)** — Turn the current conversation into a spec and publish it to the issue tracker. No interview, just synthesizes what you've already discussed.
- **[wizard](./wizard/SKILL.md)** — Generate an interactive bash wizard that walks a human through steps only they can perform: provisioning infrastructure, setting up credentials or CI secrets, walking an unfamiliar third-party dashboard, or running a one-off migration or cutover.
- **[how](./how/SKILL.md)** — Explain how code works at the level of a senior engineer onboarding onto a subsystem: Sonnet explorers map it in parallel, an explainer writes Overview, Key Concepts, How It Works, Where Things Live and Gotchas, and the gotchas become memo notes. Also the "zoom out" map of an unfamiliar area. Adapted from poteto's pstack.
- **[no-comments](./no-comments/SKILL.md)** — Strip narrating comments from a diff through Comment Sicko, a comment-hating reviewer who didn't write them; fix what they papered over at the root, and offer to encode claimed constraints as types, tests or lints. Land runs it before the worktree-janitor. Adapted from poteto's pstack.
- **[why](./why/SKILL.md)** — Find out why code is the way it is: a jj code anchor, then one Researcher per evidence category in parallel (source control, issue tracker, docs, chat, observability, errors, analytics, agent memory), and a Decider as synthesizer that writes a cited, confidence-tiered answer with the gaps named, plus Preserve / Change / Avoid / Risk before a change. Company sources yield engineering rationale only. Adapted from poteto's pstack.
- **[explain](./explain/SKILL.md)** — Explain a change, PR or subsystem plainly so you understand it now: `how` and `why` do the digging, and one conversational account comes back, definition first, smallest complete answer, diagrams built up one part at a time. Adapted from poteto's pstack (its `teach`).
- **[architect](./architect/SKILL.md)** — Design before code: ground with `how` (and `why` when ownership moves), sketch the types, signatures and module map through `arena` from competing candidates screened against codebase-design's red flags, then implement against the sketch and scrap it on a pattern of friction. A checkpoint only when asked. Adapted from poteto's pstack.
- **[arena](./arena/SKILL.md)** — Run N parallel attempts at one task, each runner an Implementer under a distinct constraint in its own jj workspace; a blind Decider scores them against a rubric, then pick a base and graft the best of the others by hand, with a synthesis note. Adapted from poteto's pstack.
- **[figure-it-out](./figure-it-out/SKILL.md)** — Design a bespoke, auditable playbook when no tuca-mode playbook fits (a large migration, a cross-cutting change, work you review after stepping away): frame a falsifiable done, design the units as jj changes, run a hypothesis loop, keep the trail with `show-me-your-work`, verify on the real product. Adapted from poteto's pstack.
- **[swarm](./swarm/SKILL.md)** — Fan out N parallel workers over slices or race arms (coverage matrices, races, gauntlets, exploration partitions), drain them, and return one PASS / ISSUES / BLOCKED table; a race declares `first pass`, `rank all` or `best-of` up front. Sonnet workers for legwork, Opus for code-writing race arms in their own jj workspaces. Pick it over `orchestrate` (code changes partitioned by file) and the coordinator (standing programs) when the result is a verdict. Adapted from poteto's pstack.
- **[create-verification-skill](./create-verification-skill/SKILL.md)** — Generate a project-local `.claude/skills/verify-<app>/` skill that launches the app and drives it the way a user does (claude-in-chrome for web, tmux or direct commands for CLIs and TUIs, HTTP for services): Launch, Doctor, Drive, Evidence, Cleanup and a feature map, proven end to end once before handing over. Claude Code's `run` picks it up too. Adapted from poteto's pstack.
- **[maintain-verification-skill](./maintain-verification-skill/SKILL.md)** — Keep a verify skill honest: Sonnet source readers per feature, then one live pass driving every feature under three invariants (doctor first, evidence survives cleanup, no residue), ending clean, changed (one jj change of proven corrections) or blocked. Adapted from poteto's pstack.
- **[prototype](./prototype/SKILL.md)** — Build a throwaway prototype to answer a design question — either a single shareable HTML file for state/logic questions, or several radically different UI variations, each on a named axis, behind a fixed picker on one route.
- **[lang-c](./lang-c/SKILL.md)** — C rules and taste, attached to `*.c`/`*.h`: C23 on GCC 16 / Clang 23, warnings as errors, sanitizers, clang-tidy, the testing ladder in C (Unity, libFuzzer/AFL++, Mull), and QMK keymap specifics; versions pinned in `references/sources.md`.
- **[lang-cpp](./lang-cpp/SKILL.md)** — C++ rules and taste, attached to C++ sources, `CMakeLists.txt` and `meson.build`: C++23 (C++26 where pinned), Core Guidelines ownership and RAII, `std::expected`, hardened standard library, sanitizers, and the testing ladder in C++ (GoogleTest/Catch2, rapidcheck, FuzzTest, Mull). Research-only: no C++ repos of Luiz's yet.
- **[lang-refresh](./lang-refresh/SKILL.md)** — Keep the `lang-*` skills current: `lang-sources` lists every row of their `references/sources.md`, one Sonnet agent per skill checks each row against official release notes and registry APIs, and a verdict per skill (current, adopt, breaking) becomes one jj change per skill in a `lang-refresh` workspace for review. Monthly through `/schedule`, and on a language's major release.
- **[lang-py](./lang-py/SKILL.md)** — Python rules and taste, auto-attached on `.py`, `pyproject.toml` and `uv.lock`: uv for every environment, ruff and basedpyright as gates, frozen dataclasses and one exception per failure, the testing ladder mapped to pytest, syrupy, Hypothesis (stateful too), atheris and mutmut, and worker pools sized from memory.
- **[lang-go](./lang-go/SKILL.md)** — Go rules and taste, auto-attached on `.go` and `go.mod`: modern idioms deferred to JetBrains' use-modern-go, gates picked per repo (gofmt, go vet, golangci-lint v2 or staticcheck, go fix), sentinel errors and `%w`, small interfaces with hand-written fakes, and the testing ladder on rapid, `go test -fuzz`, gremlins and testing/synctest.
- **[lang-nix](./lang-nix/SKILL.md)** — Nix rules and taste, auto-attached on `.nix`, `flake.lock` and `devenv.yaml`: the latest release from an unstable input or upstream (never stale stable), nothing applied to a real machine by an agent, the dotfiles' dendritic modules, out-of-store links and overlay packages, devenv per project, `nix fmt` and `nix flake check` as gates, and NixOS VM tests through the dotfiles' nixvm skill.
- **[lang-nu](./lang-nu/SKILL.md)** — Nushell rules and taste, auto-attached on `*.nu` and `*.nuon`: the bash habits that break (and `>` that silently writes nothing), external failures captured with `complete` where pipefail does not reach, typed signatures and `def main`, explicit sub-module imports since 0.114, Luiz's config edited in the dotfiles, `nu-check --debug` as the gate, and `std/assert` tests (no bundled `@test` runner yet). Checked on the installed 0.115.1 against 0.116.1.
- **[lang-cs](./lang-cs/SKILL.md)** — C# and .NET rules and taste, auto-attached on `.cs`, `.csproj`, `.slnx` and `.razor` files: .NET 10 and C# 14, nullable discipline, records, analyzers and `dotnet format` gates, Microsoft.Testing.Platform through `global.json`, the testing ladder in .NET tools (TUnit, Testcontainers, Verify, CsCheck, SharpFuzz, Stryker.NET), and Box and Temporal .NET gotchas.
- **[lang-rust](./lang-rust/SKILL.md)** — Rust rules and taste, auto-attached on `*.rs` and `Cargo.toml`: the fmt/clippy `-D warnings`/nextest gate, no panics on outside input, `SAFETY:` and `#[expect(..., reason)]`, anyhow with context, trait seams with hand-written fakes, and the testing ladder in Rust (insta, proptest, cargo-fuzz, cargo-mutants, loom/shuttle/turmoil). Built from Luiz's Rust repos and the official docs.
- **[lang-ts](./lang-ts/SKILL.md)** — TypeScript rules and taste, auto-attached to `.ts`/`.tsx`/`.mts`/`.cts` files: parse at boundaries, typed failures, strict contracts, Vite+ gates, the testing ladder's TypeScript tools (fast-check, StrykerJS, Jazzer.js), topic files for Effect and Cloudflare, and a sources table the refresher keeps current. Adapted in part from poteto's pstack (MIT).
- **[lang-zig](./lang-zig/SKILL.md)** — Zig rules and taste, auto-attached on `*.zig`, `build.zig` and `build.zig.zon`: the Zig 0.16 `std.Io` and build APIs that stale training data gets wrong, explicit allocators with `defer`/`errdefer`, TigerBeetle's TIGER_STYLE habits (assertion density, bounds, units-last names), and the testing ladder in Zig (`std.testing`, seeded PRNG loops, `zig build test --fuzz`). From official docs only; Luiz has no Zig repo yet.
- **[lang-swift](./lang-swift/SKILL.md)** — Swift rules and taste, auto-attached on `*.swift` and `Package.swift`: Swift 6.4 and Xcode 27, value types first, the 6.2 concurrency model (main actor by default, `@concurrent`, actors last), `some` before `any`, swift-format and SwiftLint gates, Swift Testing, and the testing ladder in Swift. From official docs; Luiz has no Swift repo yet.
- **[lint-evolve](./lint-evolve/SKILL.md)** — Turn a lesson that repeats into a rule in the language's native linter (Oxlint JS plugins, clippy/dylint, .NET analyzers, ruff, golangci-lint, clang-tidy, statix): evidence from reflect's backlog, review and interrogate findings, comment-sicko, memo gotchas and automate-me; the native lint first, else a custom rule tested on the real incident; a read-only trial across Luiz's repos recorded in `lint/registry.toml`; a jj change proposing it at warn.
- **[lint-audit](./lint-audit/SKILL.md)** — Audit the lint rules: trial the unmeasured ones, promote clean rules toward error and retire silent ones on Luiz's answer, point rules that keep firing at the skill that should teach better, and re-vendor updated packs into each repo through `lint-vendor` (a jj workspace and change per repo, nothing pushed).
- **[worktree-janitor](./worktree-janitor/SKILL.md)** — Shape a messy jj `@` into a clean, described stack through the worktree-janitor agent (split by intent down to single hunks with `jj-hunk-pick`, fixups absorbed, conflicts resolved, messages in the repo's style, empty `@` on top; siblings joined by a merge when asked), then audit it mechanically with `janitor-audit`: same final tree, nothing below the stack touched, one `jj op restore` to undo.
- **[principles](./principles/SKILL.md)** — Twenty-three engineering principles (laziness, root causes, prove it works, model the domain, guard the context window…), an index of one line each and a file per principle, adapted from poteto's pstack (MIT).
- **[tuca-mode](./tuca-mode/SKILL.md)** — `/tuca-mode`: the working mode for the rest of the session. Every task is routed to a playbook (bug fix, feature, refactoring, land, workspace prune…) whose steps open the todo list, with the principles, the autonomy and reply rules, and a coordinator's mindset; it survives compactions until "stop tuca-mode". Adapted from poteto's pstack (MIT).
- **[animate](./animate/SKILL.md)** — Build one animation the way a strict review would pass it: decide whether it should animate at all and why, then the tool, properties, curve and duration or spring, interruption and exit, with reduced motion and hover gating in the same change; recipes for the common components. Also names a motion effect from a loose description (its vocabulary).
- **[review-animations](./review-animations/SKILL.md)** — Review a diff's motion against ten standards (justified, frequency-appropriate, ease-out, under 300 ms, origin, interruptible, GPU-only, accessible, asymmetric, cohesive): a Before/After/Why table, findings by impact tier, then Block or Approve. `review` runs it for UI diffs that add or change motion.
- **[improve-animations](./improve-animations/SKILL.md)** — Audit a codebase's motion (recon, Sonnet readers per category, vetting at file:line) and write self-contained fix plans under `plans/` that any agent can execute; `execute <plan>` runs one in its own jj workspace and reviews the result. Never edits source.
- **[find-animation-opportunities](./find-animation-opportunities/SKILL.md)** — Find the few places that should start to animate, each through a frequency, purpose, speed and function gate with exact values, and list the candidates it rejected and why. Read-only.
- **[design-engineering](./design-engineering/SKILL.md)** — Craft rules for web UI polish (press states, origins, transforms, clip-path, gestures, performance, accessibility) and the Before/After/Why review table, with a map to the narrower UI skills.
- **[apple-design](./apple-design/SKILL.md)** — Apple's fluid-interface principles for the web: response on pointer-down, interruptible springs, velocity handoff, momentum projection, rubber-banding, materials, typography and reduced motion, with Apple's values.
- **[mobile-native](./mobile-native/SKILL.md)** — Make a web app feel native on a phone: a symptom table (sticky hover, tap flash, `100vh`, input zoom, tap delay, overscroll, notch, long-press, carousel axes, status bar) mapped to one-line CSS or meta-tag fixes, a baseline for new apps, and real-hardware testing.
- **[pick-ui-library](./pick-ui-library/SKILL.md)** — Pick a frontend library from a curated list (base-ui, cmdk, sonner, motion, recharts, dnd kit, Virtuoso, zustand, clsx, cva…) instead of hand-rolling a component, after checking what the project already has.
